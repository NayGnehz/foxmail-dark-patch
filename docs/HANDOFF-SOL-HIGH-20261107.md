## 优化任务与完成标准

1. 从 5.0 的 41 项发布清单反向追踪实际生成链，整理每个采用模块的入口、输入、输出、
   安装与回退路径及守卫。将已撤回试验、旧版源码和未装候选分开列出。结合调用者、引用
   和运行证据判断冗余。
2. 检查 PE、DFM、PNG 定位与替换、旧值与哈希校验、白名单差异核验、语义调色板、
   安装回退及发布脚本中的重复。只有共同约束稳定时才抽取公共逻辑。版本化的地址、
   原生布局和资源状态需要各自清晰的守卫。
3. 检查异步显示门和现用原生/辅助模块的状态、时序与边界。关注精确 owner 匹配、
   关闭过程、显示恢复、焦点/DPI 和异常处理。优先修复可复现问题并消除重复路径。
   现用生成器的反向恢复证明和实际 DLL 合成窗口测试是重要证据。
4. 分批落地优化并验证。资源/DFM 先核对精确差异与渲染结果，二进制桥接保留 ABI
   测试，异步 helper 保留合成生命周期验证。需要时用隔离候选验证后再做实际窗口验收。
   交付变更前后证据、测试范围及可用回退。5.0 归档供差分与恢复。

回归范围包括首次启动和托盘恢复、写信/回复/转发、Alt+A 截图白边、关闭编辑窗、
120 DPI 和字体清晰度、屏幕多色文字及 caret、导出与打印原色、设置页边框和切换、
搜索框及左右按钮、联系人标题/列表/选中、详情、新建/编辑联系人和新建组。
未读邮件滚动和偶发关闭错误有独立诊断记录，当前没有证据表明其原因已修复。
已冻结的 MSAA 防护源码尚未安装。提醒窗实际来信效果亦缺独立验收。
故障历史见 [滚动与关闭诊断](unread-scroll-fault-20261106.md)。

## 执行边界与成本

- 先读 `D:\Dev\AGENTS.md` 与当前 README。使用
  `Invoke-FoxmailPipeline.ps1 -Script <项目脚本> -Tool node|python -InstanceId version587-20261105`，
  同一实例按 lease 串行运行。正常 GUI 用 Normal 启动。
- 用户已授权对通过路径和哈希核验的 Downloads 深色副本进行必要的停止和更新。
  原版和其他程序的运行按其独立边界处理。分析使用软件静态文件、合成数据和必要的
  只读窗口数值。真实邮件、账号、联系人、签名、凭据、未知日志和完整内存转储
  不属于审查数据。UIA/MSAA 探测曾触发故障，默认避免录屏、全窗捕获及全进程内存扫描。
- 保留其他未提交源码和既有候选。特别留意 `secondary-windows/compose-native-gate/foxmail_reveal_gate.c`、
  `secondary-windows/compose-surface-candidate/`、两份 compose trace 入口及
  `version587/*safe-read*`、`msaa-node-read*`。Git 只提交明确归属的文件，使用
  `Contributor <>`，本地提交。各版本封存和历史证据按原始状态保存。
- **按子任务难度选择子代理模型和推理强度，避免浪费 token。** 路径清单、机械核对和
  摘要可交轻量模型，普通实现可用 Sol 中等，复杂 Win32、CEF、ABI 与生命周期审查
  再用高推理。只委派互相独立且能提供不同证据的工作，分配必要文件和边界，
  避免让多个代理重读整段历史或重复运行相同检查。
  [OpenAI Docs 子代理模型选择](https://learn.chatgpt.com/docs/agent-configuration/subagents)
